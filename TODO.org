* Allgemeines

** Ziel

Für mehrere Dictionary-Sources (z. B. Duden, DWDS, OpenThesaurus, Wiktionary) sollen Requests *asynchron gleichzeitig gestartet* werden.

Jede Source implementiert dieselbe öffentliche API und liefert das Resultat in einem gemeinsamen plist-Format zurück.

Die Argumente und internen Bezeichner bleiben auf Englisch, auch wenn das Package sonst deutsch ist.

** Korrigierte Architektur

Der Aggregator sollte direkt in =woerterbuch-core.el= liegen.

Begründung:

- dort liegen bereits die gemeinsamen Datenstrukturen und Hilfsfunktionen
- der Aggregator ist keine UI-Schicht, sondern gemeinsame Infrastruktur
- =woerterbuch.el= kann dadurch bewusst dünn bleiben
- so verhindert man, dass Logik versehentlich zwischen =core= und =woerterbuch.el= auseinanderläuft

*** Dateien

- =woerterbuch-core.el=
- =woerterbuch.el=
- =woerterbuch-duden.el=
- =woerterbuch-dwds.el=
- =woerterbuch-openthesaurus.el=
- =woerterbuch-wiktionary.el=

*** Verantwortlichkeiten

**** =woerterbuch-core.el=
Gemeinsame Infrastruktur:
- section handling
- common result helpers
- error/result constructors
- buffer/header helpers
- gemeinsame Request-Helfer
- *Aggregator für alle Sources*
- ggf. zentrale Source-Reihenfolge oder Source-Registry

**** =woerterbuch-<source>.el=
Jeweils source-spezifisch:
- URL building
- HTTP request via =url-retrieve=
- parsing of HTML or JSON
- extraction of requested sections
- returning a normalized plist result

**** =woerterbuch.el=
Nur öffentliche Hülle:
- =require= von =woerterbuch-core.el=
- =require= der einzelnen Sources
- ggf. sehr kleine öffentliche Einstiegspunkte
- keine eigentliche Aggregator- oder Parsing-Logik
